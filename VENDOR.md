# Vendored verify core

This Action copies the public verifier. It does not `npm install` a CodeRifts-operated package and it does not fetch keys at verify time.

| File | Source | Revision |
|------|--------|----------|
| `src/verify.js` | `receipt-verifier/verify.js` | `6048195` (sha `363e52c7`; not HEAD — 1355 only touched comments) |
| `src/arity.js` | `receipt-verifier/arity.js` | bytes unchanged `e6955a97`..HEAD (`721fcac5`) |
| `src/verify-bundle.js` (and grant/attest/toolset/atomic) | same names in receipt-verifier | `d69ab53` |

The pin is **mixed on purpose**. Collapsing `src/VENDOR.sha256` to a single `receipt-verifier <sha>` would lie: verify.js is 6048195, the bundle set is d69ab53, arity is older and unchanged. Do not recopy HEAD until verify.js behavior actually moves.

SHA-256 of those copies at vendor time is in `src/VENDOR.sha256`, and `test/vendor-core.test.js` fails if the files drift from it. Do not edit the copied files in this tree; recopy from receipt-verifier.

`src/from-dsse.js` is a MIRROR of `receipt-verifier/to-dsse.js`'s `fromDSSE`, not a byte copy — it is pinned by its own constants test (`test/dsse-input.test.js`). Unpacking is not verification.

## The shared cross-language corpus

`test/fixtures/xlang-vectors.json` is a copy of the corpus generated by
`receipt-verifier/test/gen-xlang-vectors.js`, the same file the Python verifier is checked against.
Its digest is pinned in `src/VENDOR.sha256` like the vendored core.
receipt-verifier does **not** commit `xlang-vectors.json` (the generator uses an ephemeral
key, so the bytes are a run artifact). Hashing a missing
`receipt-verifier/xlang-vectors.json` yields the empty-string sha `e3b0c442…` — that is
not a corpus pin. The real path is this tree's `test/fixtures/xlang-vectors.json`
(`3c323e74…`).

The generator signs with an ephemeral key, so regenerating produces different bytes for the same
cases — the copies are not expected to be byte-identical to each other over time, only to cover the
same vector ids, key states and expected verdicts. `receipt-verifier/test/xlang-corpus-sync.test.js`
checks that structurally across every sibling checkout it can find, and names any it cannot.

To update: regenerate in receipt-verifier, copy the file here, and update the digest line in
`src/VENDOR.sha256`.
